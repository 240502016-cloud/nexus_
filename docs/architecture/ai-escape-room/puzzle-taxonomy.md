# Puzzle taxonomy

Every type has a deterministic oracle and at least one non-visual interaction path. “LLM role” always means flavor/wording over an already generated instance, never solution selection or correctness.

| # | Type | Inputs and solution representation | Validation | Difficulty controls | Three-player cooperation | Accessibility | LLM role | Ambiguity risk |
|---:|---|---|---|---|---|---|---|---|
| 1 | Exact keypad code | Fixed-alphabet string; leading zeroes significant | Constant-time exact equality | length 3–8, alphabet size, number of fragments | digits/fragments split across screens; one enters | labeled keypad, paste/keyboard, no timing precision | keypad/label flavor | Low if format and digit order are explicit |
| 2 | Normalized word/phrase | Locale-tagged text plus finite alias allowlist | Pinned NFKC/case/space/punctuation pipeline then HMAC equality | phrase length, synonym aliases, extraction depth | each player owns part of definition/acrostic | screen reader text, dyslexia font, language shown | fictional document wording inside fixed extraction slots | Medium; control with finite aliases and no fuzzy match |
| 3 | Ordered symbol sequence | Array of symbol IDs | Equal length and element-by-element hash equality | 3–8 symbols, ordering rule complexity | one sees symbols, one timestamps, one rule | symbols also have names/numbers/patterns | cosmetic symbol descriptions | Low when symbol IDs are visible |
| 4 | Set selection | Unique element-ID set | Cardinality + set equality | candidate count, distractors, predicate count | each player rules out a different subset | checkbox list, non-color tags | item names/flavor | Low; duplicates rejected before validation |

## Shared difficulty rules

- Difficulty changes information quantity, dependency depth and distractors—not smaller text, lower contrast, shorter motor windows or obscure cultural trivia.
- No required solution depends on color, audio, rapid clicking, external web search, Party Lore memory or English-specific wordplay unless the session language explicitly selects a localized template.
- Every puzzle exposes its answer format before submission. Binary feedback is the default; positional/correct-count feedback exists only when the template formally includes it and the uniqueness solver accounts for it.
- Brute-force surface is rate-limited and expected search space is linted. Rate limiting is not used to repair an underconstrained puzzle.
- A template that accepts more than one intended answer must explicitly list all finite aliases/valid states or declare “any valid path” with a deterministic predicate. The LLM cannot create an alias after seeing a submission.
